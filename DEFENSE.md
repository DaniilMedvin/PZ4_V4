# Захист: практична робота № 4, варіант 4

## Завдання

1. Створити XML-документ з даними про 3 навчальні дисципліни: назва, кількість годин, кількість кредитів, викладач.
2. Перевірити правильність XML, відкривши його в браузері.
3. Написати скрипт, який розбирає XML і виводить в HTML дисципліну з найбільшою кількістю годин (назва, години, викладач).
4. Виконати те саме для JSON: створити JSON з такими самими даними та скрипт, що виводить запис з максимумом годин.

## Структура проєкту

```
index.html              сторінка з результатами
data/disciplines.xml    дані у форматі XML
data/disciplines.json   ті самі дані у форматі JSON
src/app.js              розбір XML і JSON, пошук максимуму, вивід у HTML
src/style.css           оформлення
```

## Стек

Чисті HTML, CSS та JavaScript (ES-модуль). Без фреймворків, збірки та залежностей: усе працює в браузері.

## Формат даних

XML: кореневий елемент `<disciplines>`, всередині три елементи `<discipline>` з дочірніми `<name>`, `<hours>`, `<credits>`, `<teacher>`.

JSON: об'єкт з масивом `disciplines`, кожен елемент має поля `name`, `hours`, `credits`, `teacher`.

| Назва                        | Годин | Кредитів | Викладач         |
|------------------------------|-------|----------|------------------|
| Веб-технології               | 120   | 4        | Коваленко О. М.  |
| Бази даних                   | 150   | 5        | Шевченко І. П.   |
| Алгоритми та структури даних | 90    | 3        | Бондаренко Т. С. |

Очікуваний результат: **Бази даних, 150 годин, Шевченко І. П.**

## Як працює скрипт (`src/app.js`)

1. `init(kind)` завантажує файл через `fetch`. Якщо файл недоступний (наприклад, сторінку відкрито через `file://`), показується поле вибору файлу вручну.
2. `parseXml(text)`: `DOMParser` перетворює текст на XML-документ. Наявність `parsererror` означає, що документ некоректний. Далі `querySelectorAll('discipline')` дає список вузлів, кожен перетворюється на об'єкт `{name, hours, credits, teacher}`.
3. `parseJson(text)`: `JSON.parse` перетворює текст на об'єкт, масив `disciplines` мапиться до такого самого формату.
4. `maxByHours(items)`: `reduce` проходить масив і залишає запис з найбільшим `hours`. Функція спільна для XML і JSON.
5. `renderWinner(target, item)` будує DOM-елементи та вставляє їх у сторінку через `textContent`, тому дані не інтерпретуються як HTML.
6. `renderTable(items)` виводить усі дисципліни, рядок з максимумом підсвічується.

Обидва джерела мають однаковий внутрішній формат, тому логіка пошуку максимуму та виводу не залежить від формату файлу.

## Чому потрібен сервер

Браузери забороняють `fetch` для локальних файлів (`file://`). Тому сторінку запускають через локальний сервер:

```
cd "D:\Projects\Homework\PZ№4_V4"
npx serve
```

Після цього відкрити адресу, яку виведе команда (зазвичай `http://localhost:3000`). Без сервера можна відкрити `index.html` і вибрати файли з папки `data` вручну.

## Перевірка XML у браузері

Відкрити `data/disciplines.xml` у браузері. Коректний документ відображається деревом тегів. Помилка в розмітці дає повідомлення про помилку розбору.

## Дизайн

Оранжевий максималізм: товсті чорні рамки, жорсткі тіні, великий шрифт Unbounded, візерунки на CSS (смуги, крапки, шахівниця, зигзаг). Є темна тема, видимий фокус для клавіатури, підтримка `prefers-reduced-motion` та адаптивна верстка.

## Можливі запитання на захисті

**Чим XML відрізняється від JSON?**
XML розмічений тегами, підтримує атрибути та просторі імен, докладніший. JSON коротший, прямо відповідає об'єктам і масивам JavaScript.

**Як перевірити коректність XML?**
Відкрити в браузері, або перевірити в коді через `parsererror` після `DOMParser`.

**Чому `hours` перетворюється на число?**
З XML значення приходить рядком. Без `Number()` порівняння було б рядковим: `"90" > "150"`.

**Що робить `reduce`?**
Проходить масив, тримає поточного «лідера» і замінює його, коли знаходить елемент з більшим `hours`.

**Чому `textContent`, а не `innerHTML`?**
`textContent` вставляє дані як текст, це захищає від впровадження розмітки або скриптів.

**Чому не спрацьовує `fetch` при відкритті файлу двома кліками?**
Політика безпеки браузера блокує читання локальних файлів з `file://`. Рішення: локальний сервер або вибір файлу вручну.
